# 性能复测结果

## BPE 单进程编码

TinyStories 训练文本前约 8 MiB，10,110 篇完整文档，2,037,821 个 token；每种版本测量 5 次。计时不包含读写文件、初始化及多进程启动。

| 版本 | 中位数吞吐 tokens/s | 相对当前版本 |
| --- | ---: | ---: |
| current | 305,789 | 1.000 倍 |
| optimized_no_cache | 302,200 | 0.988 倍 |
| optimized_lru_cold | 2,048,321 | 6.698 倍 |
| optimized_lru_warm | 2,309,742 | 7.553 倍 |

四种版本全部 token ID 的 SHA256 相同。每轮开始时清空缓存的 LRU 版本达到基线 6.698 倍；只比较关闭缓存与开启缓存的优化函数，达到 6.778 倍。预热同样本后的 7.553 倍单独报告。

## KV Cache

RTX 4070 Laptop GPU，4 层 StdRes、d_model=512、FP32，同一个 step_9001.pt 检查点。使用 TinyStories 验证集真实 token，固定生成 64 token，temperature=1.0、top-p=1.0，不因 EOS 提前结束。

每个长度选择 3 个输入位置，每个位置预热 3 次，测量 7 次。下表分别对缓存开关的 21 次总耗时取中位数，用 64 / 中位数耗时计算吞吐。包含 prefill 和采样。

| 前缀长度 | 无缓存 tokens/s | 缓存 tokens/s | 倍数 |
| ---: | ---: | ---: | ---: |
| 64 | 135.04 | 146.50 | 1.085 |
| 128 | 153.81 | 145.67 | 0.947 |
| 192 | 137.04 | 137.27 | 1.002 |
| 256 | 138.42 | 152.49 | 1.102 |
| 512 | 108.26 | 141.95 | 1.311 |
| 768 | 56.13 | 137.39 | 2.448 |

64–192 token 前缀下，没有稳定的吞吐收益；768 token 前缀下约为 2.5 倍。加速倍数随前缀长度、模型规模和运行环境变化。

256–768 token 前缀的补测将 RoPE 预计算表设为 1024 个位置。检查点仍是在 256-token 上下文中训练的同一份权重；此结果验证计算性能，不评价超出训练长度的文本生成质量。两个版本均不截断历史。

长前缀正确性检查通过，512-token 前缀后单 token 增量输出的最大绝对误差为 2.19345e-5，块大小 4 时为 1.95503e-5。所有端到端测速组的两种方式都生成了相同 token ID 序列。

## 实现检查

- Tokenizer 中缓存版 encode 当前在注释里。测速脚本在内存中恢复原函数，没有改写原分词文件。
- decoding.py 的输入分支开关 using_cache 与模型构造器的 using_cache 必须一致。如果仅改前者，模型会缺少历史 K/V。测速脚本统一设置每层开关并清空缓存。
- 每层缓存保存已经应用 RoPE 的 K 及原始 V，序列维度拼接正确；位置索引随缓存长度递增，因果掩码覆盖已有历史与新增 token。
- 本次测量避开缓存窗口淘汰问题；所有生成长度都在运行时分配的 RoPE 表范围内。
